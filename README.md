# Зоря.нет — клиент участника

Клиент сети Зоря.нет на React + TypeScript (часть 1 конкурса «Зоря 2026») и Node-наблюдатель эфира, который регистрирует в просвет автоматически. Из этого клиента в части 3 вырастет штаб.

Документы конкурса — в `docs/`, план — в [`ROADMAP.md`](ROADMAP.md).

## Требования

- Node.js **24+** (наблюдатель запускает TypeScript напрямую, без сборки).
- pnpm 11 (`corepack enable` или `npm i -g pnpm`).

## Установка и запуск

```bash
pnpm install --frozen-lockfile     # строго по lockfile
cp .env.example .env               # впишите отпечаток ключа печати из ТЗ §3
pnpm dev                           # веб-клиент: http://localhost:5173
```

Продакшн-сборка: `pnpm build`, затем `pnpm preview` или любая раздача статики из `apps/client/dist`.

### Настройки (`.env` в корне)

| Переменная | Что это |
| --- | --- |
| `VITE_ZORIA_SERVER` | сервер при первом запуске: `stand` или `prod`. Дальше переключается в «Настройках» без пересборки (CL-40) |
| `VITE_ZORIA_PROD_FINGERPRINT` | SHA-256 ключа печати боевого сервера (64 hex) из ТЗ §3. Пусто — ключ не сверяется с ТЗ, клиент показывает предупреждение |
| `VITE_ZORIA_STAND_FINGERPRINT` | то же для стенда (необязательно) |
| `VITE_ZORIA_STAND_API` | подменить адрес стенда, например локальным моком |

Адреса по умолчанию: боевой `https://zoria.net/api/v1`, стенд `https://stand.zoria.net/api/v1`.

## Наблюдатель (автоматическая регистрация)

Слушает `GET /ether` раз в 15 с и проверяет печать каждого кадра. По первому подписанному кадру `phase: "window"` отправляет заготовленную заявку. После регистрации следит за статусом доступа, письмами и частями задания и присылает уведомления.

```bash
mkdir -p ~/.config/zoria
cp apps/watcher/watcher.example.json ~/.config/zoria/watcher.json
chmod 600 ~/.config/zoria/watcher.json        # в файле пароль — без 0600 наблюдатель не запустится
$EDITOR ~/.config/zoria/watcher.json          # server, fingerprint, mode, account, notify

pnpm watcher ready        # одна проверка готовности к просвету
pnpm watcher selftest     # контрольные кадры A–D офлайн
pnpm watcher check        # ключ + один кадр эфира с выбранного сервера
pnpm watcher run          # долгий режим
```

- `mode: "watch"` — только слушать и оповещать; `mode: "register"` — ещё и регистрировать.
- `account.invitation` — одноразовый **код заявки** от организаторов (с 22.09, контракт 1.1.0); на стенде — `STAND-2026`.
- `account.repositoryUrl` — любой ваш **частный** репозиторий на GitHub.
- Пароль и код живут в `~/.config/zoria/watcher.env` (0600): `ZORIA_PASSWORD=…`, `ZORIA_INVITATION=…`. Наблюдатель перечитывает файл каждый раз, когда они нужны, поэтому код можно вписать после запуска — перезапуск не нужен. Пока кода нет, он предупреждает при старте, при провозвестнике и в просвете.
- Состояние (токен, ключ, глушение, журнал `events.jsonl`, `heartbeat`) лежит в `~/.local/state/zoria/<server>/` с правами 0600. Сюда попадают и `X-Request-Id` для сообщения о сбое.
- Уведомления: на рабочий стол через `notify-send` (включены всегда, отключаются `"desktop": false`), плюс `notify.url` — POST текста на любой вебхук (например, ntfy.sh) и `notify.telegram` — бот и чат.
- Для работы круглосуточно есть systemd-юнит: `scripts/zoria-watcher.service`; инструкция в шапке файла.
- **Спящая машина пропустит просвет.** На время окна поставьте drop-in `scripts/zoria-watcher-nosleep.conf`: наблюдатель будет держать блокировку сна, пока работает. Инструкция по установке и откату — в шапке файла.

Запасной вариант без наблюдателя: `scripts/register.sh <логин> "<имя>" <owner/repo>` читает пароль с терминала и при потерянном ответе сначала проверяет вход, а не регистрирует второй раз.

## Локальный стенд (мок)

Для разработки без сети: те же маршруты, подпись учебным ключом из спецификации, помехи, лимит и глушение, сжатый цикл фаз.

```bash
pnpm mock --cycle 120 --noise 0.35         # цикл 2 минуты
VITE_ZORIA_STAND_API=http://localhost:8787/api/v1 \
VITE_ZORIA_STAND_FINGERPRINT=f3a436df65614f08635f18fe0f64f145285203f1faa2905ecb25ffb90969a7de \
  pnpm dev
```

Мок — это не сервер организаторов: его поведение взято из спецификации и может расходиться с настоящим стендом в деталях.

## Самопроверка на стенде (спецификация, раздел 6)

Стенд поднимут до 23.09. Один запуск укладывается в часовой цикл стенда: скрипт слушает шум, ловит провозвестника и переход в просвет, а в просвете проходит сценарии S3–S9. Каждый запуск регистрирует новый одноразовый аккаунт с кодом `STAND-2026`.

```bash
pnpm stand-check --repo <ваш owner/repo>                 # запускать до :20 UTC, чтобы поймать провозвестника
pnpm stand-check --repo <owner/repo> --invitation <код>  # если учебный код стенда сменили
pnpm stand-check --repo <owner/repo> --jam-test          # плюс S8: намеренно превысить лимит (только стенд)
```

Код выхода 0 — все сценарии сошлись.

## Проверка жеребьёвки (26.09)

Своя реализация приложения А оценивания, без кода организаторов:

```bash
pnpm verify-draw --draw draw.json --me <логин>   # обязательство из ТЗ §7 уже зашито
# или по частям:
pnpm verify-draw --secret <64 hex> --logins logins.txt --me <логин>
```

Раунд drand берётся с двух и более зеркал. Скрипт проверяет правило маяка, обязательство, соль и перестановку и показывает ваше место. Код выхода 0 — всё сошлось.

## Бот части 2 (`bot/`)

Отдельный npm-пакет, вне pnpm-воркспейса: части 2 нужен `npm ci` в новом checkout (P2-01), и общий лок-файл этому мешает. Пакеты `@zoria/*` берутся из частного реестра конкурса, секрет — только в переменной среды:

```bash
curl -fsS -H "Authorization: Bearer $ZORIA_HUB_TOKEN" https://zoria.net/api/v1/me/registry-token > ~/.zoria-registry.json
export ZORIA_NPM_AUTH=$(node -p "require(process.env.HOME + '/.zoria-registry.json').auth")

cd bot
npm ci                         # или npm install в первый раз
npm run play -- --fast         # три партии локального пакета, полный газ
npm run play                   # темп 500 мс на такт, как в зачёте
npm run spar                   # то же в одном процессе + базовая линия, без провода
npm run tourney                # шесть составов соперников × жеребы, средняя доля
node crown.js                  # граф сети в конце партии: циклы, обхват, вінець
npm test                       # хост-тесты: раскладки против констант спецификации
npm run mutate                 # StrykerJS: мутационный счёт по dist (К4)
npm run mutate:part 'dist/harvest.js:1-200'   # то же по диапазону строк, если машину жалко
npm run lint:nakaz             # три ступени линтера приказа
npx zaria-kit version          # хеш движителя и версии пакетов
npx zaria-kit docs             # где лежат шесть документов части 2 (сняты в docs/part2/)
```

Стратегия — `src/harvest.ts`, пресет «жатва»: берёт ничьи руины (8 тактов и 0 заряда против 60 заряда за свою голку), мостит обратно на нить свои погасшие голки, ставит на лоты, перед зорёй ждёт у кольца Ключника. Разбор правил и что пресет намеренно не делает — `../ROADMAP.md`, 6.3. Зеркала архетипов остались доступны для спарринга: `ZARIA_PRESET=обхідник npm run play -- --fast`.

Все мерительные скрипты идут под `nice -n 19` с одним пулом V8, а Stryker — в один воркер: на восьми ядрах полный прогон съедал машину целиком и ронял редактор вместе с собой. Медленнее, зато доживает до конца.

`npm run tourney` — шесть составов соперников (зеркала архетипов, образцы грамот и наш собственный `nakaz.yaml`) на каждом жеребе, с базовой линией на каждом составе. Средняя доля за партию: **2.29 против 1.83** у базовой линии. Состав со звёздочкой в среднюю не идёт — в нём соперником стоит наш же `nakaz.yaml`, и его правка делает соперника сильнее, а среднюю ниже, хотя голова не менялась. `node crown.js` — не доли, а механизм: граф горящих голок в конце партии, его циклы и обхват; им закрыт вопрос про вінець (`../ROADMAP.md`, 6.3). Ручки турнира: `TOURNEY_BASE=0` (без базовой линии), `TOURNEY_PAIRS=1,3` (только эти составы), `TOURNEY_TICKS`.

`npm run spar` — второй прибор: тот же движитель и те же соперники, но без сокетов и без дедлайна 500 мс, поэтому он мерит только решения головы. Ручки пресета переопределяются на прогон (`SPAR_DIALS='{"reach":26}'`), разбор счёта — `SPAR_WHY=1`. Дедлайн, повернення и приказ проверяет только живой `npm run play`.
